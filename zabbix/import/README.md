# Swarm exporter hosts for Zabbix 8.0

Import `swarm-exporter-hosts.yaml` (or select JSON format and import `swarm-exporter-hosts.json`) in **Data collection → Hosts → Import**. Allow creation of host groups, hosts, and items. The file creates 35 hosts in the `Zabbix Swarm exporters` group. Do not enable the option to delete missing objects when updating an existing installation.

Seventeen hosts target the individually named PostgreSQL exporters, pgSCV collectors, PgBouncer exporters, Patroni REST APIs, etcd APIs, and ClickHouse native Prometheus endpoints. Each host has an HTTP agent master item and dependent numeric items with Prometheus pattern preprocessing. Each endpoint is configured by the `{$METRICS.URL}` host macro. Collection is assigned to the Zabbix server by default, so the active server must be attached to the `zabbix_backend` overlay. To collect through a proxy instead, register the proxy and assign the hosts to it in the frontend.

The 18 node-exporter, process-exporter, and cAdvisor hosts are imported disabled. These exporters are Swarm global services; their common service names distribute connections across tasks and cannot reliably identify an individual node. Before enabling each host, provide a stable, individually addressable endpoint in `{$METRICS.URL}`. The `REPLACE-manager-N` and `REPLACE-worker-N` names are placeholders and are not functional DNS names. The existing services do not publish node-specific host ports. Do not point all six hosts to the same Swarm service VIP or to `tasks.<service>`: that can attribute one node's measurements to another. If container IPs are used temporarily, they can change when tasks restart.

The raw master item keeps no history; dependent metrics retain numeric history. This initial import contains selected metrics, not an exhaustive set, low-level discovery rules, or alert triggers. The TimescaleDB items target the `public.history` hypertable. Check **Monitoring → Latest data** and item status after import. A working HTTP endpoint does not by itself prove that its exporter can query its backend; check the PostgreSQL/PgBouncer `up` items and any unsupported items. The cAdvisor metric included here confirms its reported version, not individual container measurements.

The overlay is encrypted; do not expose these unauthenticated metrics endpoints to the public internet. See the Zabbix 8.0 [host import documentation](https://www.zabbix.com/documentation/current/en/manual/config/xml_export_import/hosts) and [Prometheus discovery documentation](https://www.zabbix.com/documentation/8.0/en/manual/discovery/low_level_discovery/examples/prometheus).
